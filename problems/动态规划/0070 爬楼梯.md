# 爬楼梯

## 题面

假设你正在爬楼梯，到楼顶需要 `n` 阶。每次可以爬 **1 或 2** 个台阶，问有多少种不同的方法爬到楼顶？

样例：
- `n = 2` → `2`（`1+1`、`2`）
- `n = 3` → `3`（`1+1+1`、`1+2`、`2+1`）

约束：`1 ≤ n ≤ 45`。

## 思路

**Pattern：DP 入门 · 斐波那契型** —— 感受「状态 + 转移方程」的第一题。

### 核心：站在第 i 阶，回头看"最后一步"

到第 `i` 阶的最后一步只有两种可能，且不重叠、恰好覆盖全部情况：

- 从第 `i-1` 阶跨 **1** 步上来 → 有 `dp[i-1]` 种走法通到这
- 从第 `i-2` 阶跨 **2** 步上来 → 有 `dp[i-2]` 种走法通到这

两类相加，即得转移方程。这一步「回头看最后一步」是 DP 拆解的精髓。

### DP 四步

| 步骤 | 内容 |
|---|---|
| 状态 | `dp[i]` = 爬到第 `i` 阶的方法数 |
| 转移方程 | `dp[i] = dp[i-1] + dp[i-2]` |
| 初始化 | `dp[1] = 1`、`dp[2] = 2`（最小、拆不动的格子，手动填）|
| 遍历顺序 | `i` 从 3 到 n，从小到大（`dp[i]` 依赖更小下标，得先算好）|

### 三种写法的演进（本题精华）

同一个转移方程，两个方向：

1. **纯递归（自顶向下 top-down）**：顺着转移方程直接翻译成 `return climb(n-1)+climb(n-2)`，直觉最自然。**但不"记账"** → `f(i)` 被反复从零重算 → 时间 **O(1.6ⁿ)** 指数爆炸（LC 卡 `n≤45` 才侥幸能过，是"坏解"）。
2. **记忆化递归**：加一个 `memo` 数组，每个 `f(i)` 只算一次、第二次直接查账 → 打回 **O(n)**。
   > ⚠️ `memo` 必须建在递归函数**外面**（全程共享一张账本）。建在里面 → 每层递归都 new 一张空账本 → 记账失效 → 退化回 O(1.6ⁿ) 超时。
3. **递推 for（自底向上 bottom-up）**：把记忆化"压平"成迭代，从小到大填，天然不重复、不吃递归栈。← **主解**

> top-down（顺着定义拆）和 bottom-up（从小往大填）是**同一个转移方程的一体两面**。
> DP 完整拼图 = **递推关系 + 记账（消除重复）**。

## 完整代码（主解：for 递推）

```go
func climbStairs(n int) int {
    if n <= 2 {
        return n
    }
    dp := make([]int, n+1)
    dp[1], dp[2] = 1, 2
    for i := 3; i <= n; i++ {
        dp[i] = dp[i-1] + dp[i-2]
    }
    return dp[n]
}
```

## 填表演示（n = 5）

| i | 1 | 2 | 3 | 4 | 5 |
|---|---|---|---|---|---|
| `dp[i]` | 1 | 2 | 3 | 5 | 8 |

`dp[3]=dp[2]+dp[1]=3`，`dp[4]=dp[3]+dp[2]=5`，`dp[5]=dp[4]+dp[3]=8` → 答案 **8**。

## 复杂度

**主解（for 递推）**

- **时间：O(n)**——一个 for 从 3 到 n，每步 O(1)。
- **空间：O(n)**——`dp` 数组长 `n+1`。因为只用到前两个值，可用滚动变量优化到 **O(1)**（留给 0509 斐波那契自己写）。

**对比 · 纯递归（劣解，仅记录，不归档代码）**

- **时间：O(1.6ⁿ)**——数递归树的节点总数。树高 ≈ n（决定「n 次方」这个指数），但右孩子 `f(n-2)` 比左孩子矮一层、树长不满，每层增长倍数 ≈ φ(1.618) 而非 2，故底数是 1.6 不是 2。
- **空间：O(n)**——只看递归栈的最大深度。`f(n-1)+f(n-2)` 加号两边**串行**执行（先算完左整支并弹栈，才算右），任意时刻栈上只有一条「爷→父→子」的直系链，最深 ≈ n。
  > 对照：**时间**数整棵树所有节点（含重复），**空间**只看最深一条路径——节点不会同时挤在栈上。
