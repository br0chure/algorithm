# 打家劫舍 II

## 题面

在 [0198 打家劫舍](0198%20打家劫舍.md) 基础上，房子排成一个**环**——首尾相邻，`nums[0]` 和 `nums[n-1]` 不能同时偷。求最大金额。

样例：
- `[2,3,2]` → `3`（三间互相相邻，只能偷一间）
- `[1,2,3,1]` → `4`（偷 0、2 号：`1+3`）

约束：`1 ≤ n ≤ 100`，`0 ≤ nums[i] ≤ 1000`。

## 思路

**Pattern：house_robber（环形变体）** → [dp_intro](../../patterns/动态规划/dp_intro.md)

核心：**别对环直接推 dp**（环没有天然头尾，别扭）。把环剪成线，复用 0198 的线性 rob。

### 环比直线，只多一条边

环和直线所有相邻约束都一样，**唯一多出来的**就是首尾边 `(nums[0], nums[n-1])`。要让它失效，只要保证**两端至少空一个**：

- **A：不偷首** → `nums[0]` 出局 → 对 `nums[1:]` 线性 rob
- **B：不偷尾** → `nums[n-1]` 出局 → 对 `nums[:n-1]` 线性 rob
- **答案 = max(A, B)**

最优方案对首尾无非四种，只有「首尾都偷」被环禁止：偷首不偷尾→落 B，不偷首偷尾→落 A，首尾都不偷→A、B 都含（取 max 不影响）。三种全覆盖。

### 为什么偏偏挑首尾这条边？（啃过的坑）

**铁律：最优方案在环的每一条边上都至少空一端**（否则违反相邻约束）。所以挑**任意一条边**当接缝都对，答案都是同一个最优值——环是对称的，从哪剪无关结果。

那为什么选首尾？纯粹**图方便**：把环写成数组后，线性 rob 自动处理所有"数组里挨着"的边，**唯独首尾边 `(n-1, 0)` 数组两端不相邻、它看不见**——首尾是唯一没人管的边。挑它当接缝，`nums[1:]` 和 `nums[:n-1]` 两个现成切片一削就完事，不用重排数组。

## 完整代码（断环成链 + O(1) 滚动）

```go
func rob(nums []int) int {
    if len(nums) == 1 {
        return nums[0]
    }
    return max(steal(nums[1:]), steal(nums[:len(nums)-1]))
}

// steal：线性打家劫舍，O(1) 滚动变量版
func steal(nums []int) int {
    if len(nums) == 1 {
        return nums[0]
    }
    first := nums[0]                 // dp[i-2]
    second := max(nums[0], nums[1])  // dp[i-1]
    for i := 2; i < len(nums); i++ {
        first, second = second, max(nums[i]+first, second) // 往前滚一格
    }
    return second
}
```

> `first, second = second, max(nums[i]+first, second)`：Go 多重赋值，右边先整体算完再赋，省掉临时变量。

## 复杂度

- **时间：O(n)**——两趟 `steal`，各扫约 n 个元素，O(2n)=O(n)。
- **空间：O(1)**——滚动变量常数个；`nums[1:]`/`nums[:n-1]` 是**切片视图**（只造新 header、共享底层数组、不拷贝元素），O(1)，不把空间拉回 O(n)。

> Go 细节：**切片表达式 `s[a:b]` 不拷贝底层数组，是 O(1) 视图**。切子数组时不必担心空间涨。
