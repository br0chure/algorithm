# 将有序数组转换为二叉搜索树

## 题面

给你一个**已升序排列**的整数数组 `nums`，将其转换为一棵**平衡**二叉搜索树（左右子树高度差 ≤ 1）。

样例：
- `nums = [-10,-3,0,5,9]` → 一种合法输出：

```
      0
     / \
   -3   9
   /   /
 -10  5
```

约束：节点数 `1 ≤ n ≤ 10^4`，`-10^4 ≤ nums[i] ≤ 10^4`，nums **严格升序**。
答案不唯一，LC 用专用 checker 验证 BST + 平衡。

## 思路

**Pattern：bst · 二分递归构造**——这道题不在树上递归，**是在数组上递归**。

### 关键反推

题目两个约束**联立**逼出选根方式：

- **BST + 升序输入** → 根的中序前是左子树、中序后是右子树 → 数组**中点**是根
- **平衡** → 左右子树节点数尽量相等 → 选**正中点**让左右等分

两条合一：**取数组中点为 root，左半数组递归造左子树，右半数组递归造右子树**。

### 三问

| 问题 | 答案 |
|---|---|
| 1. 递归返回什么？ | `*TreeNode`，新建子树的根指针 |
| 2. base case？ | `len(nums) == 0` → `nil`（空数组对应空子树） |
| 3. 当前层做什么？ | 取中点 build 节点，左右半数组递归构造 Left / Right |

## 完整代码

```go
func sortedArrayToBST(nums []int) *TreeNode {
    if len(nums) == 0 {
        return nil
    }
    mid := len(nums) / 2
    return &TreeNode{
        Val:   nums[mid],
        Left:  sortedArrayToBST(nums[:mid]),
        Right: sortedArrayToBST(nums[mid+1:]),
    }
}
```

### 为什么 `len == 0` 就够当 base case？

跟踪 `nums = [1]` 一次就明白：

```
sortedArrayToBST([1])
  mid = 0, Val = nums[0] = 1
  Left  = sortedArrayToBST(nums[:0]) = sortedArrayToBST([])  → return nil
  Right = sortedArrayToBST(nums[1:]) = sortedArrayToBST([])  → return nil
  return &TreeNode{Val: 1}    ← Left/Right 都是 nil（默认零值）
```

**单元素数组**走两次递归（左空 + 右空），都被 base case 接住返回 nil，完美。
**两元素以上**同理——递归自然下沉到 len==0 处停下。

> **写递归通用心法**（脑子记，不进 pattern）：base case 选**最小能让递归成立的输入**（树是 `nil`、数组是 `len==0`）。中间情况让递归自然处理，**不要手动拦截 len==1、len==2**。手动拦截会写出冗余分支。

### 关于 Go 切片边界

```go
s := []int{1, 2, 3}
s[3:]    // → []  长度 0，不 panic ✓
s[4:]    // panic：out of bounds
```

切片起始 index **可以等于 `len(s)`**——返回空切片。所以 `nums[mid+1:]` 在 `mid+1 == len(nums)` 时安全（如 `nums=[1,2]`、mid=1、nums[2:]=[]）。

## 与 BST 其他题的对比

| 题 | 思路方向 | 用 BST 性质 |
|---|---|---|
| 098 验证 BST | 自顶向下检查 | 左小右大 / 中序有序 |
| 230 第 k 小 | 中序遍历提前停 | 中序有序 |
| **108 升序数组转 BST** | **自顶向下构造** | **中序有序的反推**（升序中点 = 根） |

108 是 BST 系列里**唯一的"构造型"**——前两题在已有树上提取信息，这题从无到有建一棵树。

## 复杂度

- **时间：O(n)**——每个节点恰好被构造 1 次（一次 `&TreeNode{...}` 是 O(1)），总 O(n)。
- **空间：O(log n)**——递归栈，每次取中点切半，递归深度 = 树高 ≈ log₂(n)。
  - 由于"取中点"保证了平衡，树高总是 log n（不会退化成链状）——**比一般 DFS 题的 O(h) 更紧**。
  - 不计输出本身（构造的树是返回值）。
