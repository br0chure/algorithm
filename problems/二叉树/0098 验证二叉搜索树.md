# 验证二叉搜索树

## 题面

给你一棵二叉树的根节点 `root`，**判断它是否是有效的二叉搜索树（BST）**。

BST 定义：
- 节点的左子树**只包含小于**当前节点的数
- 节点的右子树**只包含大于**当前节点的数
- 左右子树自身**也必须**是 BST

样例：
- `[2,1,3]` → `true`
- `[5,1,4,null,null,3,6]` → `false`（节点 4 的左子树有 3，违反 4 < 3 的右子树规则）
- `[2,2,2]` → `false`（BST 要求严格小 / 大，等于不行）

约束：节点数 `1 ≤ n ≤ 10^4`，`-2^31 ≤ Node.val ≤ 2^31 - 1`。

## 思路

**Pattern：bst**——BST 有两条核心性质，对应两条验证方法：

| 性质 | 验证方法 |
|---|---|
| 左小右大（递归对每个子树） | **方法 1：上下界递归**（自顶向下传范围） |
| 中序遍历得到严格升序 | **方法 2：中序遍历检查升序**（自左向右扫） |

> 两种思路完全独立——哪个顺手用哪个。本归档把两种都留下，对比能加深对 BST 的理解。

## 方法 1：上下界递归

每个节点都有一个**允许的取值范围 `(lo, hi)`**——递归时把范围作为参数传下去，每往下一层范围就**收紧**：

- 进入左子树时，上界变成当前节点值（左子树所有节点必须 < 当前）
- 进入右子树时，下界变成当前节点值（右子树所有节点必须 > 当前）

### 三问

1. 递归返回什么？ `bool`（当前子树在给定 `(lo, hi)` 下是否合法）
2. base case？ 空节点 → `true`
3. 当前节点做什么？ 检查 `lo < root.Val < hi`，再递归左右子树（范围收紧）

### 代码

```go
import "math"

func isValidBST(root *TreeNode) bool {
    var bst func(*TreeNode, int, int) bool
    bst = func(node *TreeNode, lo, hi int) bool {
        if node == nil {
            return true
        }
        if node.Val <= lo || node.Val >= hi {
            return false
        }
        return bst(node.Left, lo, node.Val) && bst(node.Right, node.Val, hi)
    }
    return bst(root, math.MinInt, math.MaxInt)
}
```

> ⚠️ 初始 `lo` / `hi` 用 `math.MinInt` / `math.MaxInt`——题目允许节点值是 `INT_MIN` / `INT_MAX`，所以严格 `<` / `>` 比较时要让初始边界比所有可能值更"宽"。

## 方法 2：中序遍历检查升序

BST 的中序遍历必然是**严格升序**序列。不需要先把整棵树存成数组——**边遍历边检查**：维护一个 `prev` 指针记录上一个访问的节点，每访问当前节点比一下。

### 三问

1. 递归返回什么？ `bool`（当前子树中序是否严格递增）
2. base case？ 空节点 → `true`
3. 当前节点做什么？ 先递归左 → 检查 `prev.Val < node.Val` → 更新 `prev` → 再递归右

### 代码（AC 主解）

```go
func isValidBST(root *TreeNode) bool {
    var prev *TreeNode
    var bst func(*TreeNode) bool
    bst = func(node *TreeNode) bool {
        if node == nil {
            return true
        }
        if !bst(node.Left) {
            return false
        }
        if prev != nil && node.Val <= prev.Val {
            return false
        }
        prev = node
        return bst(node.Right)
    }
    return bst(root)
}
```

> 为什么需要闭包？`prev` 是「跨节点共享的状态」——每次访问当前节点要看上一个节点。这个状态既不能放在递归参数里（每次调用是值拷贝），也不该用包级 `var`（污染）。**闭包局部变量 + 内嵌函数捕获** 是最干净的方式。

## 两种方法对比

| | 方法 1 上下界 | 方法 2 中序遍历 |
|---|---|---|
| 用 BST 哪条性质 | 左小右大 | 中序有序 |
| 共享状态 | 不需要（参数携带） | 需要 `prev`（闭包） |
| 何时短路 | 当前节点超出范围立刻 false | 找到 prev ≥ cur 立刻 false |
| 边界陷阱 | 初始 `lo/hi` 必须用 `math.MinInt/MaxInt`（题目允许极端值） | 无 |
| 通用性 | 大多数 BST 题（98、108 等） | 中序相关 BST 题（98、230 等） |

**两种都掌握的好处**：未来刷 230 BST 第 k 小时就用方法 2 的中序套路；刷 96 / 95 不同 BST 数量时用方法 1 的上下界。

## 复杂度

两种方法量级一致：

- **时间：O(n)**——每个节点恰好被访问 1 次。短路（发现违反时 return）只能让常数变小，量级不变。
- **空间：O(h)**——递归栈，h 为树高（最坏链状 O(n)、平衡 O(log n)）。

  方法 1 单帧装 `node` 指针 + `lo/hi` 两个 int + 元信息，O(1)。
  方法 2 单帧装 `node` 指针 + 元信息，O(1)；`prev` 是外层局部变量，闭包按引用捕获，不复制到栈帧。
