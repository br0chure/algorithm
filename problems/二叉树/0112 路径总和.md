# 路径总和

## 题面

给你二叉树的根节点 `root` 和一个整数 `targetSum`，判断该树中**是否存在**根节点到叶子节点的路径，**这条路径上所有节点值的和等于 targetSum**。

样例：
- `root = [5,4,8,11,null,13,4,7,2,null,null,null,1]`、`targetSum = 22` → `true`（路径 `5→4→11→2`）
- `root = [1,2,3]`、`targetSum = 5` → `false`
- `root = []`、`targetSum = 0` → `false`（**空树没有任何路径**）

约束：节点数 `0 ≤ n ≤ 5000`，`-1000 ≤ Node.val, targetSum ≤ 1000`。

## 思路

答案是 `bool`（**单值**）。两种解法都能 AC，看顺手：

- **解法 A：纯 DFS + 返回值 + 减法**——把"沿路径累加"翻译成"剩余目标递减"
- **解法 B：DFS + 回溯**——延续 257 的回溯模板，path 累加 + 离开弹出

## 解法 A：DFS + 返回值 + 减法

### 关键 trick

每往下一步 `targetSum -= node.Val`，到叶子时判断 `targetSum == node.Val`（剩余目标正好被叶子用完）。

### 三问

| 问题 | 答案 |
|---|---|
| 1. 递归返回什么？ | `bool`（这棵子树里是否存在和为 targetSum 的"node 到叶子"路径） |
| 2. base case？ | **两个**：`node == nil` → false；叶子节点 → `targetSum == node.Val` |
| 3. 当前节点做什么？ | 递归左/右子树，`targetSum` 传 `targetSum - node.Val`；`||` 短路 |

### 代码

```go
func hasPathSum(root *TreeNode, targetSum int) bool {
    if root == nil {
        return false
    }
    if root.Left == nil && root.Right == nil {
        return targetSum == root.Val          // 叶子：剩余 sum 是否正好被这个叶子的 Val 用完
    }
    return hasPathSum(root.Left, targetSum-root.Val) ||
        hasPathSum(root.Right, targetSum-root.Val)
}
```

## 解法 B：DFS + 回溯

延续 257 的回溯模板：维护 path 累加值，进入加、离开减；外部 `hasPath` 标志收集结果。

```go
func hasPathSum(root *TreeNode, targetSum int) bool {
    hasPath := false
    path := 0
    var dfs func(*TreeNode)
    dfs = func(root *TreeNode) {
        if root == nil || hasPath { return }
        path += root.Val
        if root.Left == nil && root.Right == nil {
            if path == targetSum { hasPath = true }
        } else {
            dfs(root.Left)
            dfs(root.Right)
        }
        path -= root.Val
    }
    dfs(root)
    return hasPath
}
```

`|| hasPath` 提供短路——找到一条路径后所有子调用立刻返回。

## 关键边界：「空树 + targetSum = 0」必须返回 false

题目定义路径必须**从根到叶子**——至少要有一个节点。空树**没有路径**，所以无论 targetSum 是什么都 false。

如果错写成：

```go
if root == nil { return targetSum == 0 }   // ❌
```

会把"无路径"误判为"和为 0 的路径"。考虑 `[1, 2]`、targetSum = 1：

```
hasPathSum(1, 1)
├── hasPathSum(2, 0) → 叶子，2 == 0 → false
├── hasPathSum(nil, 0) → 0 == 0 → true ❌ 但路径不存在！
└── false || true → true ❌（期望 false）
```

**只在叶子节点做和的判断**——把「无路径」和「路径结束」严格区分开。

## 「回溯」的判别

回溯的 3 个必要特征（缺一不可）：

1. **共享状态**（多层递归共用一个变量）
2. **进入时修改**（append、加）
3. **离开时撤销**（弹出、减）

| | 解法 A | 解法 B |
|---|---|---|
| 共享状态？ | ❌ `targetSum` 是参数（值传递） | ✅ `path` 是外部变量 |
| 撤销操作？ | ❌ 没有 | ✅ `path -= root.Val` |
| **是回溯吗？** | **不是**（纯 DFS） | **是** |

`int` 在 Go 里是**值传递**——子调用动不了父调用的 targetSum，所以解法 A 不需要回溯。如果题目改成传递一个引用类型，解法 A 也会被迫变成回溯。

## 复杂度

两种解法量级一致：

- **时间：O(n)**——每个节点访问 1 次；`||` 或 `hasPath` 提供短路。
- **空间：O(h)**——递归栈，h 为树高。无额外结构。
