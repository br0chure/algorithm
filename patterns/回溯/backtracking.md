# backtracking · 回溯

集中沉淀回溯的通用模板与心法。搭配 [tree_path](../二叉树/tree_path.md)（二叉树里的 DFS + 回溯）一起看——回溯就是它的推广。

## Pattern 概念

在一个"选择序列"上穷举所有可能：每步从候选里选一个 → 递归到下一步 → 试完回退换下一个。
典型场景：**组合 / 子集 / 排列 / 棋盘（N 皇后、数独）/ 字符串切分**。

抽象成树：**宽度** = 每步候选个数，**深度** = 要做的选择步数。

## Go 通用模板

```go
var backtrack func()
backtrack = func() {
    if 满足终止条件 {
        收集一份解（深拷贝！）
        return
    }
    for _, 选择 := range 当前候选 {
        if 不合法 { continue }   // 剪枝
        做选择                    // path 加、状态置位
        backtrack()              // 进入下一层
        撤销选择                  // path 弹、状态复位
    }
}
```

## 心法

### #1 递归 = 层数不定的 for

排列 `[1,2,3]` 要 3 层 for、`[1,2,3,4]` 要 4 层——层数随输入变，没法写"变量层 for"。
**递归就是层数不定的 for**：每深入一层 = 多套一层，自己套到终止条件为止。这是回溯用递归、而非迭代嵌套的根本原因。

### #2 二叉树递归是回溯的特例

- 二叉树：每个节点的选择**固定两个**（左 / 右）→ 写死 `dfs(Left)`、`dfs(Right)`。
- 一般回溯：每步选择是**一组**（候选数组）→ 把那两行换成 `for { 选择; backtrack(); 撤销 }`。

同一个骨架，二叉树只是"每层定宽为 2"的回溯。**会二叉树 DFS = 已经会回溯**。

### #3 终止条件用"进度尺"，不是结构边界

二叉树靠指针撞 `nil` 停（结构自带边界）；回溯没有 nil，进度得自己量——用 `len(path) == 目标` 或 `index == n` 当 base case。

### #4 收集解必须深拷贝

`path` 是共享底层数组的切片，直接存进结果会被后续回溯改乱。`make([]int, len(path)) + copy`，或 `append([]int{}, path...)`。（同 tree_path 的坑；注意 `copy` 看 `len` 不看 `cap`）

### #5 排列用 used，组合/子集用 start

判断尺：**结果在不在意顺序**。

- 在意（排列 `[1,2]≠[2,1]`）→ `used`，每层选所有没用过的。
- 不在意（组合 / 子集 `[1,2]=[2,1]`）→ `start`，只往后选：强制升序，逆序分支不生成 = 去重。

两者本质都在定义「这一层能选谁」——排列 = 所有没用的，组合 = 当前位置往后的。

## 常见变体（随刷题补全）

| 变体 | 控制重复的手段 | 代表题 |
|---|---|---|
| 排列 | `used[]` 标记（可回头选） | 0046 ✅ |
| 组合 / 子集 | `start` 指针（只往后选） | 0077 ✅ |
| 同层去重 | 排序 + `i>start && nums[i]==nums[i-1]` | 待刷 |
| 棋盘 / 网格 | 行列 / 对角线 / visited 标记 | 待刷 |
