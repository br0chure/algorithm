# 0-1 背包

`n` 个物品，每个**最多拿一次**；容量有限，求最优（最大价值 / 能否装满 / 方案数）。通用方法论见 [dp_intro](dp_intro.md)。

## 核心（起手五步）

- **① 选择**：当前物品，拿 or 不拿
- **② 约束**：拿了 → 吃掉 `w[i]` 容量
- **③ 状态**：`dp[i][j]` = 前 i 个物品、容量 j 下的最优（装什么值看目标：最大价值 / 能否 bool / 方案数）
- **④ 转移**：`dp[i][j] = 合并( 不拿 dp[i-1][j],  拿 dp[i-1][j-w[i]]+收益 )`
  - 求最大价值 → 合并 = `max`，收益 = `+v[i]`
  - 求能否装满 → 合并 = `||`，拿 = `dp[i-1][j-w[i]]`（bool）
- **⑤ 顺序**：物品 i 从小到大；容量 j 二维随意、**一维必须倒序**

## 遍历顺序（背包最阴的坑）

压成一维 `dp[j] = 合并(dp[j], dp[j-w[i]]+收益)` 时，`j` 的方向决定物品能拿几次：

- **j 倒序**（W → w[i]）→ `dp[j-w[i]]` 还是"上一行"的值 → 物品**只拿一次** = **0-1 背包** ✅
- j 正序 → `dp[j-w[i]]` 是本轮刚更新的 → 物品被拿多次 = 完全背包（下个 pattern）

## 应用题识别（LeetCode 没有裸背包，全是伪装）

看到这些信号，往背包上想：

- "从一堆数里挑一些，凑出**目标和 / 总和的一半**" → 容量 = 那个目标
- 每个数**只能用一次** → 0-1 背包
- 问"**能否**凑出" → dp 存 bool（合并用 `||`）；问"**多少种**" → dp 存计数（合并用 `+`）
- **信号**：和 / 容量有明确上界 → 复杂度 O(n×W) 是**伪多项式**，W 太大就不该往背包想
