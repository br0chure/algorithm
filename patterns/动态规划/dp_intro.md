## 一、DP 的适用信号：重叠子问题

**判断一道题要不要用 DP，就看有没有「重叠子问题」——同一个子问题被反复求解。**

一眼判断法，数两个量：

| | 不同子问题个数 | 递归树节点数 | 结论 |
|---|---|---|---|
| 普通递归（如二叉树遍历）| n | n | 相等 → 不重叠 → O(n)，**不用 DP** |
| 需要 DP（如爬楼梯）| n | 指数（1.6ⁿ）| 后者爆炸 → 全是重复 → **上 DP** |

对比锚点（一次记牢）：

- **二叉树递归 `f(node)=f(left)+f(right)`**：左右子树是两堆不相交的节点，**每个节点只有一个父亲 → 只被算一次 → O(n)**，天生不用记账。
- **爬楼梯纯递归 `f(n)=f(n-1)+f(n-2)`**：`f(n-2)` 被 `f(n)` 和 `f(n-1)` 两个父亲都要 → **重复算 → O(1.6ⁿ) 爆炸**。

> DP = 专治重叠子问题：把算过的存下来、每个子问题只算一次，指数塌回线性。

## 二、DP 的内核 vs 外壳

**内核（每题不变，缺一不可）：**

1. **状态定义** —— `dp[i]` 代表哪个子问题的答案。**这是灵魂、最难、无模板可套。**
2. **转移方程** —— 子问题之间怎么递推（状态定义对了，方程常常自己浮出来）。
3. **记账** —— 算过的存下来、不重算（`dp` 数组本身就是记账本）。

**外壳（随题而变，别当死模板）：**

| 常见形态 | 其实还能是 |
|---|---|
| for 循环 | 记忆化递归（递归 + memo，没有 for）|
| 一维 `dp[i]` | 二维 `dp[i][j]`、map |
| 开整个数组 | 滚动变量（O(1) 空间）|
| 一层、顺着填 | 多层；遍历顺序有讲究 |

## 三、DP 四步（做题骨架）

1. **定义状态**：`dp[i]` 表示什么
2. **转移方程**：`dp[i]` 由更小的状态怎么算出来
3. **初始化**：最小、拆不动的状态手动填（base case）
4. **遍历顺序**：保证算 `dp[i]` 时，它依赖的状态都已经算好

---

## 四、两个方向：top-down / bottom-up 一体两面

同一个转移方程，两条路，殊途同归到 O(n)：

- **自顶向下 top-down = 记忆化递归**：顺着"定义"往下拆 + memo 记账。
  > ⚠️ `memo` 必须建在递归函数**外面**（共享一张账本）；建在里面每层 new 一张空的 → 记账失效 → 退化回指数超时。
- **自底向上 bottom-up = for 递推**：从最小状态顺着往大填，天然不重复、不吃递归栈。

for 只是把记忆化递归"压平"成迭代。

## 五、Pattern：斐波那契型（线性递推）

**特征**：`dp[i] = dp[i-1] + dp[i-2]`，当前状态只依赖前两个。

**Go 模板（O(1) 滚动变量）** —— 既然只用到前两个值，就不必开整个数组，两个变量往前滚即可：

```go
func fib(n int) int {
    if n < 2 {
        return n
    }
    prev, curr := 0, 1               // 前两个状态
    for i := 2; i <= n; i++ {
        prev, curr = curr, prev+curr // 整体往前滚一格
    }
    return curr
}
```

> 心法：**一维 DP 若 `dp[i]` 只依赖最近几个状态，就能把整个数组降成几个滚动变量，空间 O(n) → O(1)。** 这是一维 DP 最常见的空间优化。
